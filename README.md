# NT.Payments — Independent redesign concept

Работающий прототип для интервью Head of Marketing Division. Сайт на английском, инструкции на русском. Это самостоятельная концепция кандидата, не официальный сайт NT.Payments.

## Быстрый запуск

Требуется Node.js 22 или новее. Зависимостей для локального запуска, сборки и тестов нет — `npm install` не нужен.

```bash
npm run dev
```

Открой http://127.0.0.1:4173. Если порт занят:

```bash
PORT=4174 npm run dev
```

В Windows PowerShell: `$env:PORT=4174; npm run dev`.

## Что включено

- Главная: услуги, направления, NT.Wallet, поиск киоска и поддержка.
- Host a kiosk: условия, FAQ и форма с выбором UAE/KSA/Qatar.
- Providers: предложение, процесс и отдельная форма.
- Contacts: офисы и форма обращения.
- Support: каналы поддержки, FAQ и фото.
- NT.Wallet: концепт интерфейса Liquid Glass, ссылки App Store / Google Play.
- Find a kiosk: компактный выбор Dubai/Jeddah/Doha и Google Maps, без вымышленных меток.
- Демоадминка: разделы лидов, pipeline, drag-and-drop, поиск, заметки, история этапов, экспорт JSON.
- Аналитика в текущем браузере: просмотры, CTA, начало и завершение форм.
- 12 вымышленных региональных лидов с адресами `.test`.

### Маршруты

`#home`, `#host`, `#providers`, `#contacts`, `#support`, `#wallet`, `#find`, `#admin`.

Адрес `#home/find` также открывает отдельную страницу поиска.

## Google Sheets

Формы могут отправлять заявки в три вкладки: `Hosts`, `Providers`, `General enquiries`. Им нужны заголовки в строке 4:

`Lead ID, Created, Company, Contact name, Email, Country, City, Enquiry type, Stage, Owner, Next action, Follow-up, Notes`.

1. В таблице открой **Расширения → Apps Script** и вставь `google-apps-script/Code.gs`.
2. В настройках проекта добавь Script property `SPREADSHEET_ID` с ID таблицы.
3. Запусти `setup` и разреши доступ к своей таблице.
4. Разверни скрипт как Web app: выполнять от своего имени; доступ Anyone. Таблица остаётся приватной, обработчик только добавляет заявки и не отдаёт базу.
5. Сохрани полученный адрес `/exec` в серверной переменной `SHEETS_WEBHOOK_URL`.

Для локального теста скопируй `.env.example` в `.env`, укажи свой URL и перезапусти сервер. Открой:

`http://127.0.0.1:4173/?liveForms=1#host/apply`

Без `?liveForms=1` формы на localhost остаются локальными демонстрациями. На опубликованном сайте они используют `/api/leads` и требуют настроенный обработчик. При ошибке значения не очищаются; подтверждение появляется только после успешного ответа. Один requestId не создаёт дубли.

Если используешь нативные таблицы Google Sheets, у колонки `Created` выбери обычный/неуказанный тип: скрипт устанавливает формат даты после записи. Приёмник ограничен 100 новыми записями в день и предназначен для демонстраций.

Реальный URL развёрнутого приёмника и настройки конкретного аккаунта намеренно не включены в публичный исходный код.

## Публикация из GitHub через Cloudflare Workers

В конфигурации уже объявлены статические файлы и серверные маршруты `/api/*`.

```bash
npx wrangler@4 login
npx wrangler@4 secret put SHEETS_WEBHOOK_URL
npm run deploy
```

При запросе секрета вставь URL Apps Script. Не записывай его в `wrangler.jsonc` или клиентский JavaScript. `wrangler` скачивается командой `npx` при первом запуске; нужен аккаунт Cloudflare и интернет. Если имя Worker занято, измени `name` в `wrangler.jsonc`. URL будет выдан инструментом после успешного развёртывания.

Статический вариант можно разместить на GitHub Pages из `dist/public`, но Pages не выполняет серверный proxy. Для работающей записи в Google Sheets используй серверный вариант.

Документация: https://developers.cloudflare.com/workers/static-assets/binding/

## Демоадминка и данные

`#admin` — открытый демонстрационный интерфейс, не защищённая производственная CRM. Лиды, заметки, статусы и аналитика сохраняются в localStorage конкретного браузера. Импорт примеров не заменяет ручные заявки и заметки. Никаких реальных клиентских баз и ключей в исходниках нет.

Форма на опубликованном серверном сайте сохраняет заявку в Google Sheets и локальной админке отправителя. Админка **не читает общую таблицу и не синхронизирует статусы обратно**. Для общей CRM нужны защищённая авторизация, серверные операции чтения/обновления и роли доступа. Для интервью используй вымышленные данные.

## GitHub

Распакуй архив, создай пустой репозиторий и загрузи содержимое папки проекта. Для Git CLI:

```bash
git init
git add .
git commit -m "Initial NT.Payments interview concept"
git branch -M main
git remote add origin <URL_ТВОЕГО_РЕПОЗИТОРИЯ>
git push -u origin main
```

В архиве нет `.git`, node_modules, токенов, `.env` с реальными значениями или настроек Sites конкретного аккаунта. GitHub Actions запускает только проверки и сборку, без автоматической публикации.
